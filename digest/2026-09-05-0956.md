## Changes

- You can now grant permission to individual skills within a package, not just entire packages, for finer-grained control over what's allowed.
- Running the install command for the first time now walks you through an interactive setup to choose which packages, scopes, or individual skills to permit, with a confirmation step before saving.
- A new review option lets you revisit and adjust existing skill permissions later, adding, removing, or excluding individual skills without redoing the whole setup.
- List, load, validate, and stale commands run faster by avoiding repeated file reads and recalculations.
- A broken or invalid project configuration file used to silently grant access to all skills as a fallback; it now blocks access and reports the problem file instead (breaking change).
- Skill names from installed packages are now checked for unsafe characters before being used in generated shell commands, preventing malicious names from injecting extra commands.
- Skill files are now verified to come from within their own package before their contents are read, preventing symlink tricks from exposing files outside that package.
- The built-in meta-skills now pass the tool's own validation checks, with lengthy internal details moved into separate reference files.
- Reference links shown when using the built-in meta-skills now resolve correctly regardless of which directory you run the command from.
- A broken or unreadable ancestor configuration file in a workspace no longer lets a nested app bypass inherited permission restrictions; it now fails safely and reports which file needs fixing (breaking change).
