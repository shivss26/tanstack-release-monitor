### #214 — fix(intent): avoid blocking agents when no skill matches
- fixes issue #213: hooks: PreToolUse gate blocks Edit after an observed intent load, while allowing Write

**PR description:**

## 🎯 Changes

Allow hook-installed agents to continue after checking Intent guidance when no matching skill applies.

- Treat the automatic SessionStart catalog as a completed guidance check.
- Allow `intent list` to unlock edits when the catalog has no relevant skill.
- Keep `intent load <skill-id>` support for relevant skills.
- Fail open when catalog loading fails so agents do not get stuck.
- Add regression coverage for catalog checks, no-match flows, and catalog failures.
- Update the hooks documentation and add a patch changeset.

**Linked issue #213 description:**

### TanStack Intent version

v0.3.6

### Runtime and version

Node.js v22.20.0

### Package manager and version

pnpm v11.22.0

### Describe the bug and the steps to reproduce it

Hooks installed per `intent hooks install` (project scope) into `.claude/settings.json`; Claude Code 2.1.233 running headless (`claude -p`); macOS 25.3.0.

**What happened.** In agent sessions in a consuming project, the `PreToolUse` gate denied the `Edit` tool with:

> Blocked: load matching TanStack guidance before editing. Follow this repo's TanStack guidance setup, then retry the edit.

— *after* the session had already run `intent load` for the matching package's skills (via `pnpm dlx @tanstack/intent@latest load <pkg>#<skill>`, and in one session also `npx intent load …`; both exit 0 and print the skill). The same sessions' `Write` calls to the same files passed the gate immediately. The hook's matcher covers `Bash|Write|Edit|MultiEdit|NotebookEdit`, so both tools are gated — but only `Edit` was refused credit for the observed loads.

Observed in **2 of 12 otherwise-identical sessions**, so it is intermittent. Affected agents recovered by switching to `Write`, which means the gate currently neither reliably enforces (Write passes regardless) nor reliably stands down (Edit blocked after a legitimate load).

**Partial diagnosis.** An agent in one affected session read `.intent/hooks/intent-claude-gate.mjs` and the state files under `${TMPDIR}/tanstack-intent-hooks/` and reported that the Bash-side load observations and the edit-time check appeared to land on different state keys. Possibly relevant: several `claude -p` sessions ran concurrently on the same machine (separate project copies, shared `$TMPDIR`) — if observation state is keyed by anything coarser than the session, concurrent sessions may collide.

Steps:

1. In a project with an intent-enabled package installed and allowlisted, run `intent hooks install` (claude, project scope).
2. Start several concurrent `claude -p` sessions (separate copies of the project, same machine) whose tasks require editing files.
3. Each session runs `pnpm dlx @tanstack/intent@latest load <pkg>#<skill>` (exit 0), then attempts `Edit`.
4. Intermittently, `Edit` is blocked with the message above while `Write` on the same file passes.

### #210 — chore: stabilize consumer foundations and align trust documentation

**PR description:**

## Summary

Prepare the current consumer foundation for later accepted-state and delivery work by running the existing integration suite in PR validation, removing stale repository and milestone references, fixing deterministic integration-test output, and aligning trust documentation with shipped behavior.

## Why

The PR workflow ran unit, type, lint, docs, and build targets but omitted the existing package-manager, filesystem, PnP, load, scanner, and source-policy integration suite. The docs also described merged `intent.skills`, name-only source matching, and stronger hook and agent guarantees than the current implementation provides. Correcting this base first keeps later product PRs focused and reviewable.

## Changes

- Add the existing `test:integration` Nx target to `pnpm run test:pr`.
- Remove the unused `build:core` script that targeted the deleted `packages/agents` workspace.
- Remove internal lockfile-milestone wording from the unsupported `git:` source error and add a patch changeset.
- Make the human-notice integration assertion independent of agent-environment detection.
- Remove three unnecessary type assertions that blocked the current PR lint suite.
- Document nearest-declaration `intent.skills`, accumulated `intent.exclude`, kind-specific npm/workspace selectors, package-level permission, and notice behavior.
- Separate Available, Permitted, Loaded, Delivered, Activated, and Applied, and narrow `load` and hook guarantees to what Intent can observe.

## Non-goals

This preparation PR does not introduce accepted state, `intent.lock`, snapshots, new delivery modes, symlink delivery, hooks or hook behavior changes, activation, agent target selection, new configuration, new APIs, new commands, automatic `prepare` changes, registries, hosted services, or new consumer workflows.

## Follow-ups

The planned accepted-state PR is the next product step. Delivery, maintainer experience, activation, and stable-release hardening remain separate follow-up work.
